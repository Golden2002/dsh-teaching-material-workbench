# 教学物料工作台：教师备课的功能与界面设计

- 版本：设计稿 v1.0，对应当前插件 0.3.0
- 日期：2026-11-08
- 状态：待实现。本文只给设计与排期依据，不含代码改动
- 读者：插件维护者、前端实现者、验收者、试用教师
- 依据：
  - 现有客户端 `lib/client.js`（单标签页、文件级纯文本编辑）
  - 现有 Host API `lib/workbench-api.js`
  - 现有工具 8 个：`lib/index.js` 第 584 行（init、gate、audit、repro、ground、outline、language_check、standards）
  - 门禁清单 `lib/gate.js`；中文教学语言规范 `docs/LANGUAGE.md`
  - 并行研究 `docs/TEACHER-NEEDS.md`、`docs/MEDIA-PIPELINE.md` 尚在编写。本文不依赖其结论；媒体能力的可行性以那两份为准

一句话：工作台要像一张备课桌。教师看得见讲义、课件、来源和检查结果。生成按钮只是桌上的一件工具。

## 0. 给排期者的摘要

### 0.1 P0 三条

| 编号 | 名称 | 一句话 | 依赖 |
|---|---|---|---|
| P0-1 | 案例与来源向导 | 教师输入教材与主题，十分钟内建好案例并登记来源，系统标出未核验和许可不明的条目 | 现有 init、audit、gate 的 E2-sources 与 E2-rights；新增结构化来源 API |
| P0-2 | 逐页编写与导出 | 一个时间轴段对应一页，教师逐页写课件要点、讲义正文、讲稿，旁边即时预览，一键导出 docx 与 pptx | 现有 outline、timeline；新增 pages 数据、预览视图、export 工具 |
| P0-3 | 检查中心与版本回退 | 语言、接地、门禁、版权四类问题逐条可点，能跳到出问题的页或文件行；改动前有版本，改坏可退回 | 现有 language、ground、gate、audit、repro；新增 checks 与 history API |

三条串起来，就是一名教师从空目录走到"可以上课的文件"的最小闭环，中间不依赖外部工具。

### 0.2 关键交互决策（实现时不要改）

1. 页是内容的最小单位。`pages.json` 一份数据，派生讲义、课件、讲稿、分镜四类物料。教师改一页，四类物料一起变。不做两套内容。
2. 编辑、预览、来源同屏。点预览里的文字跳到对应输入框，光标所在字段在预览里高亮；点检查条跳到出问题的页或文件行。
3. 所有修改可逆。三层回退：页内撤销、保存即生成版本、导出处发布快照。"回到上次通过"是一个按钮，不是一句说明。
4. 检查不替教师签字。问题可跳转，机械替换逐条确认，但没有"一键通过"和"忽略此项"。未执行的检查永远显示"未执行"，不显示通过。
5. 对话与界面共用一个案例目录。AI 的改动先给差异提案，教师确认后才写入。教师手改优先，冲突时并排展示，不静默覆盖。
6. 预览要诚实。P0 的预览是 HTML 近似渲染，页面顶部写明"近似预览，版式以导出文件为准"。不假装自己是 PowerPoint。
7. 视频与 Manim 只出脚本和分镜，不托管视频，不自动渲染。渲染放在 P2，且要教师显式打开。

### 0.3 边界

- 不做平台化、不收集学生数据、不做商业化，理由见第五节。
- 不降门禁：数据不对就改数据，不改判据（README 第 54 行）。
- 不新增网络请求。案例目录是唯一数据源（README 第 74 至 79 行）。

## 1. 现状与设计前提

### 1.1 现在能用什么

| 能力 | 位置 | 教师现在能做什么 |
|---|---|---|
| 发现案例 | `GET /api/cases`，`workbench-api.js:171-175` | 输入一个根目录，列出两层内含 lesson.yml 的目录 |
| 打开案例 | `GET /api/case`，`workbench-api.js:176-179` | 读到标题、已存在的登记文件、`build/` 产物清单 |
| 编辑文件 | 客户端文本域 `client.js:290-308`；`POST /api/save`，`workbench-api.js:187-196` | 选一个文件，整篇当纯文本改，点保存写回原文件 |
| 单文件白名单 | `EDITABLE`，`workbench-api.js:20-43` | 只有 22 个文本文件可写，产物和图片不在此列 |
| 语言检查 | `POST /api/language`，`workbench-api.js:205-209` | 对当前文本跑 PAEG 规则，列出违例，可整篇机械替换 |
| 门禁 | `POST /api/gate`，`workbench-api.js:197-204` | 跑 16 项 E1、E2、E3 检查，底部显示三态计数与条目 |
| 8 个工具 | `lib/index.js:584` | 对话里可让 agent 建案例、跑门禁、生成大纲、审计、记哈希 |
| 产物清单 | `readCase` 读 `build/`，`workbench-api.js:117-125` | 只看到文件名与大小，不能预览 |

### 1.2 教师用起来卡在哪

1. 看到的是文件，不是一节课。打开案例默认停在 YAML 或 CSV 源码上。教师不知道从哪改，也不知道改完对不对。
2. 没有页。`build/outline.md` 是生成物（`outline.js:64-70`）。改一页要回到 `timeline.csv` 改一行再重新生成，再生成又覆盖手工调整。
3. 没有预览。讲义长什么样、课件第 3 页放不放得下，界面上看不到。
4. 没有来源对照。`teacher-pack.md` 里的 `[S01]` 要人肉翻 `sources.csv` 才找得到发布方和页码。
5. 保存即覆盖。`POST /api/save` 直接写文件（`workbench-api.js:188-196`），没有快照、没有撤销。误删救不回。
6. 检查结果不能跳转。门禁结果是一段文字（`client.js:326-337`），教师得自己找对应文件和行。
7. 没有导出。`build/` 下的 docx、pptx 要教师另找工具做，工作台不参与。
8. 没有视频与动画的位置。时间轴、讲稿、分镜、Manim 场景都没有落点。

### 1.3 设计前提

- 案例目录即数据库。所有读写限制在绝对路径的案例目录内（`workbench-api.js:64-77`）。
- 离线、零依赖、无遥测。新功能不得引入网络服务。
- 标签页挂在 `conversation.view`（`client.js:346-351`）。教师在同一会话里既能说话让 agent 改，也能点界面改。
- 门禁语义不变：skip 不是 pass（README 第 66 行），E3 未执行不能写成通过。
- 受版权保护的原件不入库（`gate.js:420-424`）。预览不得内置教材原文阅读器。

## 2. 信息架构：从教材到可上课物料

### 2.1 主路径

```text
教师输入：教材单元、课程主题或试讲题目
        │
        ▼
[1 建案例]        情境档案：学科、学段、学习者、时长、评估、语言政策
        │
        ▼
[2 登记来源]      一手来源、定位、获取方式、许可、核验状态
        │
        ▼
[3 定目标与评估]  可观察目标、目标—活动—评估对齐、评分点
        │
        ▼
[4 排时间轴]      每段起止、教师做什么、学生做什么、产出
        │
        ▼
[5 逐页编写]      课件要点、讲义正文、讲稿、图示与动画引用
        │
        ▼
[6 预览与检查]    讲义与课件预览、语言检查、接地检查、门禁
        │
        ▼
[7 导出与上课]    docx 讲义、pptx 课件、讲稿、分镜、实施包、发布快照
        ▲
        └──────── 任意一步都能回退（版本历史）
```

### 2.2 七步里教师看到什么、能改什么、系统检查什么

#### 第 1 步：建案例

- 教师看到：新建向导，字段来自 `teaching_material_init` 的参数（`index.js:93-105`）：标题、学科、学段、学习者、场景、时长、评估方式、语言政策。右侧显示"这节课预计几页、几份物料"的预估。
- 能改：全部字段。可以从已有案例复制档案（P2）。
- 系统检查：目录必须是绝对路径，案例不能已存在（`index.js:127`）。时长与评估有默认值，不强制。
- 产出：`profile.yml`、`lesson.yml`、8 个 CSV 表头、`teacher-pack.md`、verification 模板（`templates.js:147-174`）。

#### 第 2 步：登记来源

- 教师看到：来源表。列与 `sources.csv` 表头一致（`templates.js:4`）：id、标题、发布方、日期、类型、定位、获取方式、许可、核验状态、角色、备注。表头上有三个计数：已核验一手、二手、受限。
- 能改：增删行、改字段、把"未核验"改成"已核验"（要填核验方式）。
- 系统检查：E2-sources 判一手与定位（`gate.js:221-249`），E2-rights 判许可与原件扫描（`gate.js:410-424`）。`audit` 工具另写 `verification/rights-report.md`。
- 产出：`sources.csv`、`verification/rights-report.md`。

#### 第 3 步：定目标与评估

- 教师看到：目标卡（`lesson.yml` 的 objectives）、对齐矩阵（`alignment.csv`）、评分点表（`rubric.csv`）。
- 能改：目标文字与可观察表现、对齐矩阵每格、评分点与分值。
- 系统检查：E1-alignment 判对齐空格与目标覆盖，E1-rubric-sum 判分值合计，E2-rubric-source 判 official 行有没有官方评分标准来源。
- 产出：`lesson.yml`、`alignment.csv`、`rubric.csv`。

#### 第 4 步：排时间轴

- 教师看到：横向时间条加表格。每段显示起止、环节名、教师活动、学生活动、产出。顶上有一行"合计 45 / 设定 45 分钟"。
- 能改：拖动改起止、改环节名、增删段。改总时长时提示各段按比例调整。
- 系统检查：E1-timeline 判不重叠、合计等于设定时长（`gate.js:123-145`）。
- 产出：`timeline.csv`。

#### 第 5 步：逐页编写

- 教师看到：页列表（默认每段一页）、当前页的三个视图（课件页、讲义节、讲稿），右栏是来源卡与页状态。
- 能改：标题、时长、版面、要点、讲义正文、讲稿、来源标记、图示、动画引用。可以拆页、并页、重排。
- 系统检查：输入时即时提示要点条数（阈值 `page_max_items` 为 6，`templates.js:66`）、讲稿字数与估算时长、来源编号是否存在、术语是否在 `glossary.csv` 里。右栏提供"把学生可见正文同步到 language.md"按钮，供 PAEG 检查。
- 产出：`pages.json`（新增，见 7.1）、`build/outline.md`（派生，只读）。

#### 第 6 步：预览与检查

- 教师看到：讲义分页预览、课件页预览、视频分镜（P1）、检查中心四组结果。
- 能改：改内容后退回第 5 步；机械替换逐条确认；切换预览缩放。
- 系统检查：E1 全部；E2-language 判中英间距、全角标点与套话（`gate.js:330-336`）；E2-language-paeg 跑 PAEG 规则（`gate.js:392-408`）；E2-grounding 判 claims 与 `[Sxx]` 标记（`gate.js:449-517`）；E2-knowledge 判概念映射；E1-build 判产物存在；E2-accessibility 判对比度与替代文本；E3-human 与 E3-pilot 判评审与试点证据，没有就记未执行。
- 产出：`gate-report.md`、`verification/grounding-report.md`、检查中心状态。

#### 第 7 步：导出与上课

- 教师看到：物料清单与勾选（讲义、课件、讲稿、实施包、分镜、字幕、Manim 脚本），导出后的文件列表与哈希，发布快照。
- 能改：选导出范围、选模板与配色、按 `profile.thresholds` 调字号、填课堂实施包。
- 系统检查：`repro` 记 SHA-256；E1-build 判产物；导出后核对页数与 `pages.json` 一致。
- 产出：`build/handout.docx`、`build/deck.pptx`、`build/teacher-pack.md`、`video/`、`animations/`、`verification/repro.json`。

### 2.3 页面数据模型：一份数据，四类物料

一个时间轴段对应一页。页对象是内容的最小单位。字段如下。

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | string | 页标识，如 `p03` |
| `segment` | string | 对应时间轴的环节名 |
| `minutes` | number | 本页安排分钟数，与 `timeline.csv` 对应段一致 |
| `title` | string | 页标题 |
| `layout` | string | 版面：导入页、要点页、图示页、活动页、评分页 |
| `slide` | object | 课件数据：`bullets` 数组、`visual` 对象（图 id 或动画 id、替代文本） |
| `handout` | object | 讲义数据：`heading`、`paragraphs` 数组、`task` |
| `notes` | string | 讲稿正文 |
| `sources` | string[] | 本页引用的来源编号，如 `["S01","S03"]` |
| `claims` | string[] | 本页引用的结论编号（P1，用于句级接地） |
| `media` | object[] | 媒体引用（P1）：Manim 场景、视频片段、字幕段 |
| `revision` | number | 乐观锁版本号 |

派生关系如下。

```text
timeline.csv ──┐
               ├──► pages.json ──► build/outline.md（只读大纲）
lesson.yml ────┤        │
rubric/glossary┘        ├──► build/handout.docx（讲义）
                        ├──► build/deck.pptx（课件）
                        ├──► build/teacher-pack.md（实施包）
                        ├──► video/storyboard.md + script.md + subtitles.srt（P1）
                        └──► animations/scene_*.py（P1）
```

规则五条：

1. 一个时间轴段对应一页。段内内容多时拆页，不把两段并成一页。
2. `pages.json` 是源，`build/` 是派生物。派生物每次导出重建，不手改。教师改源。
3. 来源引用写 `[S01]` 这样的标记，页级 `sources[]` 用于快速对照。两处不一致时提示。
4. 时间、评分、术语以 CSV 为准。`pages.json` 只引用 id，不复制正文，避免两处改。
5. 老案例没有 `pages.json` 时，按 7.4 的兼容策略生成草稿。

### 2.4 三个修改入口

| 入口 | 适合什么 | 写入什么 | 冲突规则 |
|---|---|---|---|
| 对话 | 整段改写、生成初稿、解释检查结果 | `pages.json` 与 CSV，经提案确认 | 先给 diff 提案，教师点应用才写入；教师有未保存改动时 agent 不动 |
| 工作台 | 逐页微调、增删页、改字段 | `pages.json` 与 CSV，直接保存 | 乐观锁 revision，过期返回 409，界面提示重载 |
| 直接改文件 | 批量替换、用外部编辑器 | 同一个文件 | 界面比对 mtime 与哈希，变了就提示重新载入 |

尺寸与折叠规则：

- 顶栏 48px：案例选择、步骤进度、保存状态、版本标记、导出按钮。
- 页签名沿用现有标签"教学物料"（`client.js:350`，面板标题取 `locale/zh.json` 的"教学物料制作工作台"）。
- 左栏 224px：七步导航，每步下方一行完成度（如"来源 4 条，2 条未核验"）。可折叠到 56px 图标。
- 主区：随步骤替换。编辑类视图用"页列表 200px 加编辑区加预览区"。
- 右栏 320px：检查中心与来源。可折叠；窗口窄于 1200px 时变抽屉；窄于 900px 时左栏折叠，预览优先占满。
- 底栏 28px：页数、时长合计、检查摘要、上次检查时间、保存时间。

各区域的关键控件：

| 区域 | 控件 |
|---|---|
| 顶栏 | 案例下拉、步骤进度、保存按钮、运行检查、版本徽标、导出 |
| 左栏 | 七步导航、完成度摘要、案例切换、返回案例列表 |
| 页列表 | 搜索、列表与缩略图切换、拖拽排序、右键菜单（复制、删除、在预览中打开） |
| 编辑区 | 见 3.3 字段表；顶部有"上一页、下一页、应用到所有页" |
| 预览区 | 视图切换（讲义、课件、讲稿、分镜）、缩放、全屏、近似预览提示条 |
| 右栏 | 检查分组、问题定位、来源卡、未接地提示、折叠按钮 |
| 底栏 | 状态摘要、检查时间、键盘提示（按 ? 打开快捷键表） |

### 3.2 视图清单

| 视图 | 入口 | 主要控件 | 空状态 | 离开保护 |

| 案例列表 | 标签页默认 | 根目录选择、案例卡片、搜索、新建 | 见 3.7 | 无 |
| 七步工作区 | 左栏导航 | 每步专属控件 | 见 3.7 | 有未保存改动时询问 |
| 逐页编辑器 | 第 5 步 | 页列表加编辑加预览 | "还没有页" | 提示保存 |
| 预览与检查 | 第 6 步 | 预览视图、检查中心 | "还没有跑检查" | 无 |
| 检查中心 | 全屏 | 四组结果、筛选、定位 | "全部通过"或"未执行 n 项" | 无 |
| 版本历史 | 顶栏版本徽标 | 版本列表、diff、恢复 | "保存一次之后出现" | 无 |
| 导出与发布 | 第 7 步 | 物料勾选、模板、导出、发布快照 | "还没有导出文件" | 提示导出中 |

### 3.3 逐页编辑（重点）

#### 页列表

- 三种显示：列表（标题加时长加状态）、缩略图、大纲（环节层级）。
- 状态点含义：灰是空白、蓝是有内容、黄是有未接地句（P1）、红是有检查失败、绿是本轮检查通过。
- 拖拽排序，顺序变更时同步调整时间轴段顺序；提示"第 4、5 页顺序已变，时间轴同步调整？"
- 搜索按标题与要点文字过滤。

#### 编辑字段与校验

| 字段 | 控件 | 校验 | 界面提示 |
|---|---|---|---|
| 页标题 | 单行文本 | 必填，不超过 30 字 | "一句话说清这页讲什么" |
| 本页时长 | 数字，步进 1 | 合计与设定时长差超过 1 分钟时提示 | "本页 5 分钟；全部 47 分钟，比设定多 2 分钟" |
| 版面 | 下拉，五种 | 图示页必须有图或动画 | "图示页还没有图" |
| 课件要点 | 逐行列表 | 最多 6 条，每条不超过 20 字 | "要点 7 条，超过 6 条上限（profile.thresholds.page_max_items）" |
| 讲义正文 | 纯文本 Markdown | 支持 `[Sxx]` 与 `![图](assets/...)`；每节不超过 400 字 | "本节 412 字，讲义预览会排到下一页" |
| 讲稿 | 多行纯文本 | 显示字数与估算时长 | "92 字，约 37 秒（按每分钟 150 字算）" |
| 来源 | 多选标签 | 编号必须存在于 `sources.csv` | "本页引用 S01、S03；S02 已删除" |
| 图示 | 从 `figures.json` 选择或上传到 `assets/` | 上传前提示版权与替代文本 | "这张图缺替代文本（E2-accessibility）" |
| 动画 | P1，从 `animations/` 选择场景 | 只允许已生成的场景 | "脚本已生成，未渲染，需要本机 manim 才能预览" |

#### 交互细节

- 编辑与预览双向定位。点预览里的段落，焦点跳到对应字段；焦点停在字段，预览里对应块加描边并滚动到可见。
- 键盘：左右方向键翻页（焦点不在输入框时），Ctrl+S 保存，Ctrl+Z 与 Ctrl+Y 撤销重做，Alt+上下移动页顺序，? 打开快捷键表。
- 自动草稿：停止输入 2 秒写本地草稿，不生成版本。点保存才生成版本。关闭页面前提示"有草稿未保存为版本"。
- 批量操作：统一版面、统一字号、批量补页、批量删空页、给选中页加同一来源。
- 页面重排与时间轴联动：拖动页顺序会来回写 `timeline.csv` 的段顺序，保存前显示变更摘要。
- 不做富文本编辑器。理由见第五节第 1 条。P0 用纯文本加 Markdown 子集，够用，也不会把排版缺陷带进导出。

### 3.4 预览（重点）

#### 讲义预览

- A4 纵向，缩放 60% 至 100%。页边显示来源角标，页脚是"讲义 · 第 x / n 页"。
- 字号取 `profile.thresholds`：正文最小 14pt，目标 16pt（`templates.js:63-66`）。低于阈值时角标提示"字号低于下限"。
- 分页按讲义节切分。一节超过一页时在预览里显示分页位置，教师可以删句或拆节。

#### 课件预览

- 16:9，缩略图条加大图。五种版面模板。配色取 `palette.json`，对比度不达标时角落标黄并给原因（WCAG 2.2 SC 1.4.3）。
- 悬停要点可以看到该条在讲义中的对应段落（P1）。

#### 视频分镜预览（P1）

- 表格式：时间码、画面、旁白、字幕、来源。
- 旁白按字数换算时长，默认每分钟 150 字，可改。超出本页时长时标红并给差值。

#### 预览的诚实原则

1. 顶部固定提示条："近似预览：版式、字体、分页以导出的 docx 或 pptx 为准。"右侧是"打开导出文件"按钮。
2. 不隐藏溢出。要点超限、段落超页、图片放不下，预览里如实显示折行与截断位置。
3. 不在预览里模拟导出后才出现的效果。动画、母版、切换效果一律不模拟，写"导出后查看"。
4. P1 接真实缩略图：调用外部渲染器渲染 `build/` 里的导出文件。失败时退回近似预览并写明原因，不假装成功。

### 3.5 对照来源（重点）

右栏三个区：本页来源、未接地提示、相关来源建议。

来源卡字段：编号、标题、发布方、日期、类型、定位（页码或 URL）、获取方式、许可、核验状态、被几页引用。

交互：

- 点正文里的 `[S01]`，右栏展开 S01 卡片并高亮；再点一次收起。
- 点来源卡的"被引用页"，页列表只显示引用该来源的页。
- 悬停来源卡，正文对应标记加底色，方便核对一段话引用了几条来源。
- 页级一致性提示：页的 `sources[]` 与正文标记不一致时显示"本页登记了 S02，但正文没有引用"。

未接地提示（P1）：

- 句末没有 `[Sxx]` 的实质句标黄，右栏显示"本页 3 句没有登记来源"。
- 点句出现三个动作：登记来源、改述、删除。三个动作都写 `claims.csv` 或改正文，不做静默改写。
- 登记来源时可选已有来源加定位，或新建来源；保存后正文自动补 `[S02]` 标记。

版权边界：

- 不显示教材原文，只显示教师自己登记的定位与允许的短引文（不超过 50 字）。
- 不内置 PDF 阅读器，不提供"整段摘录"按钮。需要核对原文时，教师在外部阅读器里按定位查看。
- 来源卡提供"复制定位"（如"人教版必修二 Unit 3，第 32 页"），方便教师自己打开书。

### 3.6 回退（重点）

三层回退，各管一段。

| 层级 | 触发 | 保存位置 | 粒度 | 恢复方式 |
|---|---|---|---|---|
| 撤销重做 | Ctrl+Z 与 Ctrl+Y | 内存 | 字段与页 | 快捷键或编辑菜单 |
| 自动版本 | 保存、门禁全部通过时 | `.history/<时间>-<原因>/` | 整份案例 | 版本历史里选"恢复" |
| 发布快照 | 导出成功时 | `.history/publish-v<版本号>/` 加 `repro.json` | 整份案例 | "回到发布 v3" |

版本历史视图：

- 左列版本列表：时间、触发原因、来源（界面、对话、导出）、页数变化、门禁三态摘要、哈希前缀。
- 右侧 diff：只显示有变化的页，点开看字段并排对比（课件要点、讲义正文、讲稿、来源）。支持并排与单栏两种显示。
- 底部按钮：恢复为新版本、复制此页内容、只看门禁通过的版本。

"回到上次通过"：

- 只在存在门禁全部通过的版本时可点，位置在顶栏版本徽标旁。
- 点击先弹确认："将放弃 7 处未保存改动（涉及 3 页），回到 11:41 通过检查的版本 v6。"两个按钮：取消、回到 v6。
- 恢复动作生成新版本，不覆盖历史，历史列表里能看到"从 v6 恢复"这一条。

冲突处理：

- 外部修改时弹窗三选一：重新载入磁盘版本、保留我的、并排查看。并排查看时左右只读，选定保留一边。
- 对话提案与手改同时发生时，以 revision 为准，过期方提示重载，不合并两份文本。

存储与清理：

- `.history/` 只存文本（`pages.json` 与 CSV 差异），不存图片与二进制，避免膨胀。
- 默认保留最近 50 个版本加全部发布快照。可在设置里清空，清空前提示导出过哪些快照。
- 版本目录随案例一起拷贝即可带走，不依赖工作台。
- 发布快照绑定 `repro.json` 的哈希，教师能回答"上课那一版的文件哈希是多少"。

| 错误 | 界面文案 | 下一步 |
|---|---|---|
| 路径不存在 | 找不到这个目录：D:\...。检查路径，或选择另一个目录。 | 重新选择 |
| 不是案例目录 | 这个目录不是案例：缺少 lesson.yml。可以新建案例，或去上一级目录找。 | 新建、返回 |
| 保存失败 | 保存失败：文件被占用或目录只读。改动还在编辑器里，没有丢。 | 重试、另存为副本 |

| 对话写入被拒 | 工作台里有未保存改动，这次的修改没有写入。先保存或放弃改动，再让助手改。 | 保存、放弃改动 |

### 3.9 文案与交互原则

- 三态用词固定：通过、不通过、未执行。不用"基本通过""可能有问题"。
- 失败文案写三段：发生了什么、影响什么、下一步做什么。界面里不写道歉。
- 长任务显示步骤进度，可取消。检查时教师可以继续看稿，不阻塞。
- 按钮用动词开头："生成页""导出讲义""回到 v6"。不用"确定""提交"。
- 不用营销词。"智能""一键""秒级"这类词不进界面。
- 数字带单位与阈值来源。例如"要点 7 条，超过 6 条上限（profile.thresholds.page_max_items）"。

## 4. 功能清单

### 4.1 判定规则

P0 满足三条：没有它，教师无法独立完成一次备课到上课；只依赖现有工具加少量新接口；验收能在界面上看见。
P1 是明显减少返工，或覆盖视频与 Manim 物料，但有外部依赖或需要更多设计确认。
P2 是体验增强、自动化或复用，缺了不影响一次完整备课。

### 4.2 P0（三条）

#### P0-1 案例与来源向导

用户故事：

- 作为教师，我在对话里说"建一个高一英语阅读课案例"，工作台要我确认 6 个字段，然后建好目录与文件。
- 作为教师，我把教材、课程标准、评分标准各登记一条，系统告诉我哪条还没核验、哪条许可不明。
- 作为教师，我想从来源表直接看到这节课的结论分别由哪条来源支撑。

入口：对话里的 `teaching_material_init`；工作台"新建案例"按钮；左栏第 1、2 步。

依赖：现有 `init`（`index.js:87-191`）、`audit`、`gate` 的 E2-sources 与 E2-rights；新增结构化来源 API（见 7.2）。

验收标准：

1. 从空目录点"新建案例"到文件生成，不超过 8 步操作，界面不出现 YAML 源码。
2. 来源表保存后，未核验条目有计数与筛选项，点计数能筛出这些行。
3. 必填字段缺失时保存，定位到第一个问题字段，并说明缺什么。
4. 登记 2 条一手来源后运行检查，E2-sources 通过；许可填 `unknown` 时 E2-rights 不通过，且能定位到该行。
5. 案例目录内放一个 PDF 后运行检查，E2-rights 不通过，文案提示"案例目录内有原始材料文件"，并列出文件名。
6. 来源表支持键盘操作：Tab 换格、上下键换行、行内按钮可聚焦。

#### P0-2 逐页编写与导出

用户故事：

- 作为教师，我排好 45 分钟时间轴后点"生成页"，得到 6 页，每页已带环节名与时长，我只需要改标题和要点。
- 作为教师，我在一页里同时写课件要点、讲义正文和讲稿，右边能看讲义和课件长什么样。
- 作为教师，我点"导出"，拿到 handout.docx、deck.pptx 和 teacher-pack.md，页数和界面一致。

入口：左栏第 4 至 7 步；主区的页列表加编辑加预览。

依赖：现有 `outline`（`outline.js`）、`timeline.csv`、`lesson.yml`、`rubric.csv`、`glossary.csv`；新增 `pages.json`、预览视图、`teaching_material_export`（见 7.3）。

验收标准：

1. 从排好时间轴到生成页，一次点击完成。页数等于时间轴段数，评分标准页与术语页单独标出。
2. 改一页标题后 1 秒内预览更新。保存后 `build/outline.md` 与 `pages.json` 的同页标题、时长一致。
3. 讲义预览按 A4 分页，页脚页码连续。课件预览为 16:9，要点超过 6 条时在预览里显示溢出警告。
4. 导出产生 3 个文件，文件页数与节数和 `pages.json` 一致，`repro.json` 记录 3 个 sha256。
5. 断网状态下完成上述全部操作。缺少导出依赖时降级为 Markdown 与 HTML，界面写明"未生成 docx 与 pptx，原因：缺少依赖"，不静默。
6. 从进入第 5 步到"改第 3 页一个要点并看到新预览"，不超过 4 次点击。

#### P0-3 检查中心与版本回退

用户故事：

- 作为教师，我点"运行检查"看到四组问题，点任何一条，界面跳到出问题的页或文件行。
- 作为教师，我误删了第 4 页讲稿，Ctrl+Z 没救回来，也能从版本历史退回五分钟前的状态。
- 作为教师，导出后还要改，改完能回到"发布 v3"继续。

入口：右栏检查中心、顶栏"运行检查"、全屏版本历史、导出后的发布快照。

依赖：现有 `gate`、`language_check`、`ground`、`audit`、`repro`；新增 checks 聚合 API 与 history API（见 7.2）。

验收标准：

1. 检查中心固定四组：门禁、语言、接地、版权。每组显示通过、不通过、未执行与条目数。
2. 每条问题带定位（页号，或文件名与行号）。点击后视图切到对应步骤并高亮。抽样 20 条问题，定位命中 20 条。
3. 门禁不通过时顶栏显示"不通过 n"；全通过为"通过"；存在未执行时为"通过 n / 未执行 m"，未执行不计入通过。
4. 每次保存自动生成版本。版本列表显示时间、原因、页数变化。恢复后文件内容与所选版本一致（比对 sha256）。
5. "回到上次通过"只在存在全通过版本时可用，点击先显示将被放弃的改动摘要。
6. 发布快照后，`repro.json` 的哈希与 `build/` 文件一致，能回答"上课版本"是哪个快照。
7. 检查未跑完、超时或报错时，界面显示"检查没有跑完"，不显示通过。

### 4.3 P1（七条）

| 编号 | 功能 | 用户故事（一句） | 入口 | 依赖 | 验收标准 |
|---|---|---|---|---|---|

## 5. 不做什么与理由

| 不做 | 理由 | 替代做法 |
|---|---|---|
| 完整 PPT 编辑器（拖拽排版、母版、动画时间轴） | 这是 PowerPoint 的地盘。工作台没有渲染内核，做一半的编辑器比不做更糟，教师会以为所见即所得 | 页级结构化编辑加近似预览，导出后在 PowerPoint 里精排。页面数据保持纯净，再导入不丢 |
| 视频托管与剪辑 | 存储、带宽、版权、学生数据边界都超出插件范围。离线插件没有流媒体能力 | 导出讲稿、分镜与 SRT，视频在外部工具合成 |
| 学生数据、学情分析、作业分发 | 隐私与合规风险高，且会让插件从备课工具变成平台。E3 只登记评审与试点文件是否存在，不存学生个体数据 | 试点数据由教师在案例目录外保存，只把汇总结果登记进 `pilot.csv` 模板（现有设计） |
| 自动放行与"一键通过" | 门禁的价值就在不签字。skip 变 pass 等于造假 | 逐条修复，机械替换逐条确认 |
| 内嵌教材原文阅读器与整本翻译 | 版权。工作台只登记定位，不复制原文 | 来源卡显示定位与教师登记的短引文，教师在外部阅读器里对照 |
| 内置 TTS 与语音合成 | 外部依赖重，声音授权与费用问题多。插件要保持离线零依赖 | 讲稿导出后交给外部 TTS。P2 只做文本导出与字数校准 |
| 实时多人协作 | 冲突同步复杂，教师备课多为单人。文件锁与版本历史已覆盖同一台机器的多入口 | 版本历史加冲突提示。需要协作时同步案例目录 |
| 自动改写教师正文 | 教师对措辞负责。静默改写会破坏语气，也破坏信任 | AI 只给差异提案与建议，教师确认后写入 |
| 学科题库与自动出卷 | 与逐条接地冲突，题目质量要学科人工把关，还会稀释证据链定位 | 评分点与 `rubric.csv` 已覆盖课堂评估 |
| 云同步、账号体系、计费 | 商业化与平台化，不在插件范围。案例目录本身可以放进任何同步盘 | 目录即数据，教师自行备份 |

## 6. 两个使用剧本

教师用时为估算，未实测。验收时按 8.2 采集。

### 6.1 剧本 A：45 分钟常规课

背景：李老师，高一英语，教材必修二第三单元阅读课（单元与页码为示例，实际以教师登记为准）。班级 45 人，45 分钟，课堂任务型评估，无正式考试。
物料：讲义 1 份 3 页，课件 6 页，教师实施包，来源 4 条。
前提：教材、课程标准、教师用书在手边。教材原文不进入案例目录。

第 1 步，建案例（约 3 分钟）

- 操作：在对话里说"建一个案例：高一英语必修二第三单元阅读课，45 分钟，45 人，课堂任务评估"。
- 界面：工作台自动切到第 1 步，向导已填好学段、时长、评估。教师补"学习者：高一平行班"。
- 点"建立案例"。提示："案例已建立：D:\...\unit-3-reading。共 20 个文件。"
- 系统检查：目录为空、路径合法。

第 2 步，登记来源（约 8 分钟）

- 界面：来源表 4 行待填，顶上计数为 0。
- 填 4 条：教材（书、单元、页码，许可：受版权保护，本地引用）、课程标准（官方网址，许可：公开）、教师用书（页码，许可：受版权保护）、自编练习（原创，许可：自编）。
- 系统提示："2 条未核验：S01、S03。核验方式：核对纸质书页码。"
- 检查：E2-sources 通过，E2-rights 通过。顶栏显示"来源 4 · 已核验一手 3"。

第 3 步，定目标与评估（约 6 分钟）

- 填 3 个目标：O1 抓住文章主旨与结构，O2 根据上下文推断词义，O3 用三句话表达对网络交友的看法。
- 对齐矩阵 3 行：读中活动对 O1，词汇任务对 O2，讨论对 O3。
- 评分点 3 条：主旨题 4 分、词义题 3 分、表达 3 分，合计 10 分，与 `lesson.yml` 总分一致。
- 检查：E1-alignment 通过，E1-rubric-sum 通过。E2-rubric-source 显示"未执行：本次是课堂任务，无官方评分标准"。

第 4 步，排时间轴（约 5 分钟）

- 5 段：导入 5，读前 8，读中 15，读后 12，小结 5。
- 第一次填成 47 分钟，界面顶上说"合计 47 分钟，比设定多 2 分钟"。点"按比例压缩"后变为 45。
- 检查：E1-timeline 通过。

第 5 步，逐页编写（约 25 分钟）

- 点"从时间轴生成页"，得到 6 页（5 段加评分标准页）。
- 第 2 页（读前）：要点 3 条；讲义正文 2 句，带 `[S01]`；讲稿 110 字，界面显示"约 44 秒（按每分钟 150 字算）"。
- 第 3 页（读中）：先写 7 条要点，界面提示"要点 7 条，超过 6 条上限"，删成 5 条。
- 语言检查：第 1 页有 2 处第二人称（两句以"同学们"开头的提问）。点问题跳到该句，改成"学生先看标题，猜文章谈什么"。
- 第 4 页有一句"网络让青少年更孤独"，页状态变黄，右栏提示"这 1 句没有登记来源"。教师删掉这句，换成教材事实的转述并挂 `[S01]`。
- 把第 2、3 页的讲义正文贴一份到 `language.md`，让学生可见文本也过 PAEG 检查。
- 保存，生成版本 v2，顶栏显示"v2 · 11:18"。

第 6 步，预览与检查（约 8 分钟）

- 讲义预览 3 页：第 2 页内容排到第 3 页一半。教师把讲义正文从 2 句压到 1 句。
- 课件预览 6 页：第 5 页图片没有替代文本，预览角落提示"缺替代文本（E2-accessibility）"。教师在图示字段补"两名学生在讨论手机使用"。
- 点"运行检查"：通过 11，不通过 1（E2-language 中英间距 1 处），未执行 4（E2-rubric-source 无官方评分标准、knowledge.csv 未填、E3 两项）。修掉间距后重跑：通过 12，不通过 0，未执行 4。
- 教师看到"未执行"没有当成通过。界面有说明"未执行不计入通过"。

第 7 步，导出与上课（约 3 分钟）

- 点"导出"，勾讲义、课件、实施包。产出 `build/handout.docx`、`build/deck.pptx`、`build/teacher-pack.md`。提示"已导出 3 个文件，发布快照 v3"。
- `repro.json` 记录 3 个哈希。顶栏显示"v3 · 已导出 11:41"。
- 上课当天早上想改一个例句：从版本历史选 v3 恢复，改完另存 v4。
- 课后复盘：同行听评意见登记进 `verification/peer-review.md`（P1 表单）。E3 从"未执行"变成"已登记"。

### 6.2 剧本 B：10 分钟试讲（含 Manim 动画）

背景：王老师，高中英语语法微课"现在完成进行时"，面试试讲 10 分钟，5 页课件，含 30 秒时间轴动画和 60 秒讲稿视频脚本。无正式评分标准。
物料：课件 5 页，讲稿，SRT 字幕，Manim 场景脚本，教师实施包。
说明：本剧本用到 P1 的媒体功能（讲稿分镜、Manim 脚本、试讲模式）。P0 阶段可以先走到第 6 步的课件预览与检查，媒体部分按 4.3 的验收标准单独验收。

第 1 步，建案例（约 2 分钟）

- 场景选"面试试讲"，时长 10，评估"无正式考试"，语言"中文为主，英文术语保留"。

第 2 步，登记来源（约 4 分钟）

- 2 条来源：教材语法附录（页码）、课程标准语法条目（官方网址）。自编例句登记为 S03，许可"自编"。
- 检查：E2-sources 通过。

第 3 步，定目标与评估（约 3 分钟）

- 1 个目标：学生能说出两种时态的差别与使用条件。
- 界面提示"试讲无评分标准，E2-rubric-source 记为未执行"。教师确认，不强行补一条假标准。

第 4 步，排时间轴（约 3 分钟）

- 4 段：问候与目标 1，规则讲解 3，动画演示 3，操练与收尾 3。

第 5 步，逐页编写（约 20 分钟）

- 生成 5 页。
- 第 3 页加动画：点"添加动画"，选 Manim，填主题"动作从过去持续到现在"、时长 30 秒、画面上要出现的 3 个时间点。界面显示"脚本已生成：animations/have_been_doing.py。未渲染，需要本机 manim 才能预览"。
- 第 2 至 4 页生成视频讲稿：每页旁白框显示字数与时长。第 3 页旁白 92 字，显示"约 37 秒，超出本页 30 秒"。教师删到 72 字。
- 语言检查：讲解句"请看这个时间轴"是祈使句，改成"画面给出时间轴，动作从过去延续到现在"。
- 保存，生成版本 v1。

第 6 步，预览与检查（约 6 分钟）

- 点"试讲模式"：全屏显示第 1 页，左上角倒计时 10:00。讲到第 4 页剩 1:20，提示"剩余 80 秒，建议跳过第 5 页练习，直接收尾"（依据时间轴分配）。
- 预演一遍后回到编辑。检查：通过 11，不通过 1（替代文本缺失），未执行 4（E2-rubric-source、E2-knowledge、E3 两项）。
- 教师补完替代文本，重跑检查：通过 12，不通过 0，未执行 4。

第 7 步，导出与上课（约 3 分钟）

- 点"导出"，勾课件、讲稿、字幕、实施包、Manim 脚本。产出 5 页 pptx、讲稿、SRT、`scene` 脚本。
- 发布快照"试讲 v1"。
- 面试前一晚改开场白：在版本历史并排对比 v1 与当前，只保留开场白这一处改动，恢复其余部分。

### 7.4 数据兼容

- 老案例没有 `pages.json`：打开时按 `timeline.csv` 生成草稿，标"草稿，未确认"。教师点"确认生成页"才写盘。
- `build/outline.md` 变为只读派生物。教师直接改它时提示"这是生成文件，请在第 5 步改页"。
- CSV 结构不改。`pages.json` 只引用 source_id、rubric 行、glossary 行，不复制正文。
- `pages.json` 顶层带 `schema` 字段。升级时写迁移，不静默丢字段。
- 版本历史不参与门禁的数据读取。`scanForbiddenFiles` 会扫整个案例目录（`gate.js:374-390`），`.history/` 只含文本、`assets/` 只放图片，都不触发现有的二进制文件名规则（`gate.js:28`）；不要把教材 PDF 放进 `assets/` 或 `.history/`。

### 7.5 与对话的协作规则

- 对话改动先写提案，界面显示 diff。教师点"应用"才写源文件。
- 教师有未保存改动时，agent 的写入请求被拒绝，提示"有未保存改动，先保存或放弃"。
- 冲突以 revision 为准。过期 revision 返回 409，前端提示重载。
- 对话里调用的工具与界面调用的是同一套 API，不出现两套写入路径。
